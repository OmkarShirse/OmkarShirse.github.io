01 / Silicon Serial Communication Fundamentals

While microcontrollers hide serial communication behind fixed hardware registers, implementing a UART on an FPGA requires building the underlying shift registers, bit-period counters, edge synchronizers, and glitch filters directly in synthesizable RTL.

The standard 8-N-1 UART protocol transmits parallel byte data across a single asynchronous physical line:

  • Idle Line: Held stably high (logic '1') when no traffic is present.
  • Start Bit: Driven low (logic '0') for exactly 1 bit-period to signal the beginning of a frame.
  • Data Bits: 8 bits serialized least-significant bit (LSB) first.
  • Stop Bit: Driven high (logic '1') for 1 bit-period to demarcate the frame boundary and reset line bias.

Because incoming serial data originates from an external, unsynchronized clock domain, directly feeding the RX pin into sequential logic causes metastability—inducing indeterminate logic levels and corrupting state transitions. Robust silicon engineering requires double-register synchronization and mid-period verification.

02 / RTL Architecture & State Machine Design

The architecture partitions cleanly into two independent synthesizable modules: the transmitter (uart_tx in UART.vhd) and the receiver (uart_rx in UART_TB.vhd), coordinated via parameterized generic timers:

======================================================================================== TRANSMITTER (uart_tx) ======================================================================================== i_tx_start (pulse) ──┐ i_tx_data [7:0] ──┤──► [ST_IDLE] │ │ (i_tx_start = '1' -> Latch data, assert busy, drive '0') │ ▼ │ [ST_START_BIT] --> Drives '0' for g_CLKS_PER_BIT cycles │ │ │ ▼ │ [ST_DATA_BITS] --> Transmits bit 0..7 (LSB first) │ │ │ ▼ │ [ST_STOP_BIT] --> Drives '1', de-asserts busy upon completion ▼ │ o_tx_serial └──► Returns to [ST_IDLE] ======================================================================================== RECEIVER (uart_rx) ======================================================================================== i_rx_serial (Async) ──► [FF Stage 1] ──► [FF Stage 2] ──► [Falling Edge Detector] │ ▼ [ST_IDLE] │ (Falling edge detected) ▼ [ST_START_BIT] │ Mid-bit check (g_CLKS/2 - 1) ├── Line = '0' --> Valid Start! └── Line = '1' --> Glitch! Abort to IDLE │ ▼ [ST_DATA_BITS] │ Sample at center of each bit ▼ [ST_STOP_BIT] │ Verify line = '1' (Stop bit) ├── Valid: Latch byte into o_rx_data, │ Pulse o_rx_data_valid <= '1' └── Framing error: Drop corrupt byte

Silicon Fix: Zero-Latency Start Bit Assertion

In naive UART state machines, asserting i_tx_start moves the FSM to ST_START_BIT on clock tick $N$, but only begins driving the physical line low on tick $N+1$. In this hardened implementation, r_tx_serial <= '0' and r_tx_busy <= '1' are asserted immediately within the ST_IDLE branch when i_tx_start = '1', eliminating startup jitter and achieving immediate cycle-accurate transmission.

03 / Parameterized Timing & Integer Rounding

The baud rate generation is fully parameterized via a single compile-time generic, g_CLKS_PER_BIT. To avoid accumulative phase drift across asynchronous clock ratios, the clock division calculation employs half-baud integer rounding:

g_CLKS_PER_BIT = (c_CLK_FREQUENCY + c_BAUD_RATE / 2) / c_BAUD_RATE

Adding c_BAUD_RATE / 2 implements round-to-nearest integer arithmetic instead of truncating division. Both modules enforce generic parameter bounds at synthesis time:

-- Enforces minimum clock oversampling margin for stable sampling assert g_CLKS_PER_BIT >= 4 report "g_CLKS_PER_BIT must be at least 4" severity failure;

04 / Synthesizable VHDL Core Implementation

The RTL is written cleanly to IEEE-1164 standards, ensuring portability across Xilinx Vivado, Intel Quartus, Lattice Diamond, and open-source toolchains (GHDL, Yosys):

-- UART.vhd: Parameterized Synthesizable Transmitter library ieee; use ieee.std_logic_1164.all; entity uart_tx is generic ( g_CLKS_PER_BIT : integer := 5208 -- 50 MHz Clock / 9600 Baud ); port ( i_clk : in std_logic; i_rst : in std_logic; i_tx_start : in std_logic; -- Pulse to initiate transmission i_tx_data : in std_logic_vector(7 downto 0); -- Parallel byte o_tx_serial : out std_logic; -- Serial bitstream out o_tx_busy : out std_logic -- High while frame active ); end entity uart_tx;

In the receiver, double-buffering ensures that downstream systems never read partial or unstable data during active shift reception:

-- UART_TB.vhd (uart_rx): Double-buffered stop bit validation when ST_STOP_BIT => if r_clk_counter < g_CLKS_PER_BIT - 1 then r_clk_counter <= r_clk_counter + 1; else r_clk_counter <= 0; -- Verify line is high (valid stop bit); latch byte only on valid frame if r_rx_sync_2 = '1' then r_rx_data <= r_rx_byte; -- Update public output register r_rx_d_valid <= '1'; -- Single-cycle completion pulse end if; r_rx_state <= ST_IDLE; end if;

05 / Automated Self-Checking Verification Suite

The verification harness tb_uart instantiates the transmitter and receiver in a closed loopback topology. Rather than relying on manual visual waveform inspection, it executes an automated assertion procedure with strict timeouts:

-- Modular verification procedure with assertion timeouts procedure check_send(constant c_data : in std_logic_vector(7 downto 0)) is begin w_tx_data <= c_data; w_tx_start <= '1'; wait for c_CLK_PERIOD; w_tx_start <= '0'; -- Wait for receiver data valid pulse with 2 ms guard timeout wait until rising_edge(w_clk) and w_rx_data_valid = '1' for 2 ms; assert w_rx_data_valid = '1' report "TESTBENCH ERROR: Timed out waiting for rx_data_valid" severity failure; assert w_rx_data = c_data report "TESTBENCH ERROR: Received data mismatch" severity failure; -- Wait until transmitter finishes wait until w_tx_busy = '0' for 2 ms; assert w_tx_busy = '0' report "TESTBENCH ERROR: TX busy timeout" severity failure; wait for 1 us; end procedure;
Test Case Bit Pattern / Scenario Verification Purpose
Test 1: `0xA5` `10100101` Validates maximum alternating bit transition density & timing integrity.
Test 2: `0x3C` `00111100` Validates nibble boundaries and multi-cycle static signal states.
Test 3: `0x00` `00000000` Boundary test: confirms start bit isn't confused with 8 consecutive data zeros.
Test 4: `0xFF` `11111111` Boundary test: confirms idle line isn't confused with all-ones payload.
Test 5: Back-to-Back `0x55` immediately followed by `0xAA` Stress test: verifies zero inter-frame gap handling without stop-bit clipping.

#!/usr/bin/env bash set -euo pipefail cd "$(dirname "$0")" # 1. Analyze VHDL-2008 sources with standard IEEE libraries ghdl -a --std=08 --ieee=standard UART.vhd ghdl -a --std=08 --ieee=standard UART_TB.vhd # 2. Elaborate testbench entity ghdl -e --std=08 --ieee=standard tb_uart # 3. Execute simulation and dump VCD waveform for GTKWave ghdl -r --std=08 --ieee=standard tb_uart \ --vcd=uart_waveform.vcd \ --stop-time=10ms
